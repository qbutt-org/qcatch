# qcatch

qcatch is the public, independently installable Windows browser media catcher in `qbutt-org/qcatch`. It also supplies qbutt's browser connection and uses qplay for playback. Neither product is required for standalone downloads. `upstream-lock.json` records source provenance; `THIRD_PARTY_NOTICES.md` and `licenses/` define redistribution requirements.

## Ownership

- `src/content/sniffer.ts` is the single MAIN-world fetch/XHR observer. `src/content/bridge.ts` owns isolated extension messaging; `src/connection/content.ts` owns exact player interaction. Keep these worlds separate and build content scripts without code splitting.
- `src/background/` owns Chrome APIs, tab state, queue and temporary DNR rules. `src/offscreen/` owns media I/O, OPFS and Mediabunny remuxing; never send media bytes through the service worker or buffer a whole output in memory. `src/shared/` has no Chrome API dependency.
- `src/connection/` owns qbutt's cookies/fetch/resolve/cancel protocol and capability-advertised `vk-search`. `fetch` returns bounded HTTP responses; qbutt's source parsers classify HTML browser checks. VK search reads the exact query's rendered result cards in one bounded, muted, inactive owned tab and closes it after success, failure or cancellation; never extract the site's hidden authorization state. The extension ID is pinned by the public manifest key and `release/extension-id.txt`. `org.qbutt.qcatch` is the only native host; never add a second embedded qbutt extension. `--version-json` and `--connect-browser edge|chrome` are protocol version 1; connection metadata returns the selected browser, extension directory/ID and native host.
- `bridge/` owns the Rust helper, standalone download queue and scoped temporary cookie jars. Its HTTP API listens only on `127.0.0.1:47832`, checks Host, extension Origin and the required request header. Native messaging mode relays bounded JSON to qbutt's current-user pipe; qbutt owns that broker and content library.
- `src/shared/platforms.ts` owns exact post/clip/track URL recognition. `src/background/platform-assets.ts` reads the selected page's accessible assets; `bridge/src/services.rs` owns local yt-dlp extraction. Reuse the existing browser or native queue. Browser data must match the requested media ID; never substitute a video thumbnail, preview, different post or guessed player state.
- qplay discovery uses Windows App Paths. Pass ordinary mpv arguments and keep playback cookie jars until qplay exits; qplay owns its configuration and engine. qbutt handoff uses `qbutt://capture` with a stable page and opaque browser-session capture ID, never a CDN URL or cookies. Changed, missing or expired captures fail explicitly rather than selecting another frame or episode.
- `scripts/qcatch.iss` owns per-user installation, App Paths, product registry metadata, startup and native-host registration. Browser extension loading remains an explicit Edge/Chrome developer-mode step until an actual store listing exists.

## Product contracts

- Capture only media already accessible to the current page. Do not bypass DRM, search for keys, upload media or browsing history to a service, or inject product UI into source pages.
- Choose maximum frame area, then bitrate; do not silently lower quality. Preserve separate audio/subtitle tracks and prefer MKV for multiple tracks. Final filenames omit quality suffixes.
- Popup selection and work survive closing the popup. Browser session state, headers and capture bindings remain in `chrome.storage.session` and are removed with their tab. Source cookies and private share URLs go only to the local helper's current task and scoped temporary files, never its durable queue.
- Downloads begin after explicit user action. Native helper outputs go to the Windows Desktop Known Folder only after completion and never overwrite existing files. Browser downloads use the browser's download destination. Preserve audio-only formats and verify full duration when the source provides it; Twitch live streams are opened in qplay rather than recorded as clips.
- Keep the `#009df7` accent, readable controls and restrained surfaces. Preserve explicit source/track/episode selection and show errors that identify the next action. Do not use `·` anywhere in user-facing UI, sites or README files, or substitute `•` or `●` as text separators.
- Write natural, connected copy without promotional slogans, sentence fragments or invented contrasts. Use real screenshots cropped to the product window.
- Keep the main interface and README available in Russian and English with a visible language switch. The interface and product site follow the browser language initially and preserve an explicit language choice.

## Verification and delivery

`bun install --frozen-lockfile`, `bun run check` and `bun run bridge:build` are the local source gates. `bun run package` builds the extension ZIP. `bun run release:build -- v1.0.0` builds installer, portable bundle, extension ZIP, dependency sources, manifest and checksums locally; set `INNO_SETUP_COMPILER` when Inno Setup 6.7.3 is outside the configured dependency directory. Ordinary GitHub releases contain only `qcatch-setup.exe` and optional `qcatch-portable.zip`. Exact runtime dependency sources are published separately under `<product-tag>-sources` and linked from the release; product source comes from its Git tag. Keep manifests and checksums local. Release tags and product manifests must agree.

Do not write unit tests. Use legal generated media and actual integration/browser/native tests: ordinary HLS, split DASH, popup reopening, cancel/restart, correct tracks and output decoding; check YouTube MP4/MP3 and time ranges when changing that path. Test standalone install/reinstall, startup, qplay playback and qbutt connection/handoff in an isolated profile. Claim site support only after its actual browser/download flow passes; a build, mock or available extractor is not proof. Do not write work reports unless requested.

Prefer clean, simple final code and one owner per state and contract. Write code, configuration and tooling for people who will maintain it: clear responsibilities, readable control flow, meaningful blank lines and multiline configuration. After meaningful edits, review unused code, abandoned hypotheses, unnecessary state, wrappers and fallbacks. После получения рабочего результата проведи абляционный проход: поочерёдно убирай добавленные абстракции, состояния, fallback-ветки, обёртки и специальный код, затем повторяй применимые проверки. Всё, без чего требуемое поведение и долгосрочная поддерживаемость сохраняются, удали. Не упрощай ценой потери ясных архитектурных границ, диагностируемости или доказанной будущей расширяемости.

After the interface works, perform separate style and text ablation passes. Remove dispensable containers, dividers, markers and effects, then slogans, duplicate labels, fragments and obvious helper copy. Inspect the real interface and repeat the affected actions after removals; retain only what supports understanding, discoverability, feedback and product identity. Repeat until a full pass removes nothing further. Source review alone does not establish visual ablation.

Preserve unrelated work and keep generated artifacts out of Git. The public repository publishes only `main`; never commit credentials, private keys, browser profiles or dumps. Build and validate locally; do not add or dispatch automated workflows. Verify actual repository visibility, outgoing diff, remote revision and release asset hashes before delivery.
